# 첫 곡 분석 충분성 판정 기준 — v1.0

> **2026-11-03 적용 정정 — 사용자 후속 지시 우선.** 재현·점검의 기준은 지정 음원의 첫 곡 실제 소리다. 아래 v1.0의 10개 항목은 분석 누락을 찾는 보조표로 사용한다. 항목을 모두 채웠다는 사실이 충분성을 보증하지 않으며, 아래 §6의 “10개 모두 충족”에 따른 자동 종료 규칙은 현재 판정 규칙으로 적용하지 않는다. 원곡의 핵심 소리를 설명하지 못하거나 재현 지시를 바꾸는 모순이 남으면 이를 구체적으로 제시한다. 당시 v1.0 본문과 사후 판정은 이력으로 보존한다. 목표를 낮추거나 새 취향을 추가하는 변경은 아니다.

고정일: 2026-11-02 (Asia/Seoul). 적용 대상: Lost in the Echoes, 지정 MP3의 0~222초. 작성: AI. 근거: 사용자가 확정한 ‘그루브·음색·공간감·편곡을 최대한 완벽하게 재현’이라는 목표와 ‘점검 때마다 기준이 바뀌지 않도록 정확한 기준을 먼저 정하라’는 지시.

이 기준은 **추가 분석 전에 고정하는 프로젝트 운영 기준**이다. 이전 분석 전에 이미 이 판정표를 적용했다거나, 사용자가 각 세부 항목을 별도로 승인했다고 기록하지 않는다. 외부 표준이 이 곡의 충분성을 보증한 기준도 아니다. 기존 음악 목표를 구체적인 점검 항목으로 풀어 썼으며 새로운 악기·장르·취향 조건을 추가하지 않는다.

## 1. 무엇을 판정하는가

판정 질문: **첫 곡의 핵심 특징을 원본 구간과 근거에 연결해 설명할 수 있고, 그 설명으로 재현 방향을 정할 수 있는가?**

- 분석 충분성은 원곡과 같은 생성곡을 이미 얻었다는 뜻이 아니다. 생성 결과의 재현 정도는 이후 별도 비교에서 평가한다.
- 목표는 네 축 전체의 최대한 완전한 재현으로 유지한다. 어떤 축이 어렵다는 이유로 ‘분위기만 비슷하게’로 낮추지 않는다.
- 장비/프리셋의 제품명, 원래 프로젝트 파일, 실제 EQ 노브·리버브 플러그인/노브의 완전 복원은 요구하지 않는다. 실제 소리의 역할·음역·음형·질감·배치·시간 변화를 설명해야 한다.
- 06은 실행·기록 방법, 08은 추가 분석 절차다. **충분성 판정은 이 문서의 v1.0에 따른다.** 기존 07 보고서는 사후 초기 점검의 증거이며 이 기준으로 사전 검증된 결과로 소급하지 않는다.

## 2. 상태와 공통 통과 규칙

| 상태 | 뜻 |
|---|---|
| 충족 | 아래 해당 행의 완료 조건을 모두 만족하며 근거 위치가 기록됨 |
| 부분 충족 | 일부 근거가 있으나 완료 조건 중 남은 항목 또는 제작 방향을 바꿀 수 있는 모순이 있음 |
| 미충족 | 해당 완료 조건을 판단할 핵심 근거가 없거나 핵심 문제가 아직 구별되지 않음 |

모든 항목에는 **주장, 원본 시각, 사용한 자료/방법, 관찰·측정·추정의 구분, 반례 확인, 남은 불확실성, 판정 이유**를 남긴다. ‘좋아 보임’, ‘많이 분석함’, ‘모델이 말했다’만으로 충족 처리하지 않는다.

- 오디오 모델의 설명은 후보 근거다. 모델 응답을 늘리거나 서로 동의한다는 사실만으로 음악적 정답을 확정하지 않는다.
- 원본의 해당 사건·소리와 대조한다. 분리 출력만 보고 악기 존재를 확정하거나, 약한 스템을 증폭해 원본의 주요 소리로 격상하지 않는다.
- 수치로 확인할 수 있는 항목은 단위·구간·처리 조건·해상도/불확실성을 함께 기록한다. 정답 박자·음표 주석이 없으면 정확도·합격률을 만들지 않는다.
- 청감으로만 갈리는 중요한 해석은 실제 사용자 청취 확인을 받거나 미충족/부분 충족으로 남긴다. AI 신호 측정·연구 모델 실행을 직접 청취로 부르지 않는다.
- 임의의 80점·90점, 모든 과제에 공통인 ms/Hz/dB 허용오차는 만들지 않는다. 분석 해상도와 추정 범위를 보고하는 것과 음악적 합격선을 정하는 것을 구분한다.

## 4. 핵심 미해결과 남겨도 되는 불확실성의 구별

판단 질문은 고정한다: **남은 두 해석이 소리의 유무·역할·음형/그루브·음색 형태·공간의 작동·편곡 전개에 서로 다른 제작 지시를 요구하는가?**

- 그렇다면 핵심 미해결이다. 상태를 충족으로 올리지 않는다. 예: 전경 보컬 단편을 넣어야 하는지 배경 신스만 유지해야 하는지, 베이스가 재발음하는지 진폭만 바뀌는지에 따라 실제 결과가 갈리는 경우.
- 같은 음향 목표를 설명할 수 있고 제작 지시가 달라지지 않는 경우에는 원인/명칭의 불확실성으로 남길 수 있다. 예: 제품명 미상, 같은 소리 특징을 만드는 리버브/신스 릴리즈의 정확한 노브 미상. 그 경우에도 소리 특징의 근거 자체는 있어야 한다.
- 불확실성에 ‘영향 없음’이라고 이름만 붙여 통과시키지 않는다. 항목 ID, 두 후보, 소리 차이, 제작 지시 차이 유무와 근거를 적는다.
- 낯선 디테일이 발견되면 먼저 기존 10개 항목 중 어디에 속하는지 기록한다. 별도의 새 합격 조건을 계속 추가하지 않는다.

현재 종합 판정: **분석 충분성 미충족, 통합 제작안 확정 단계로 넘어가지 않는다.** 두 충족 항목의 성과를 다른 미해결 때문에 폐기하지 않고, 여덟 미완료 항목만 추가 분석·대조의 대상으로 삼는다. 항목 수는 작업 관리용이며 완성도 점수/퍼센트가 아니다.

## 6. 완료·재개방·기준 변경 규칙

1. 분석 충분성은 I01~E01 **10개 모두 충족**일 때 판정한다. 빈칸을 ‘미확인’으로 채우는 것만으로 충족하지 않는다. 핵심 미해결이 남으면 그 항목과 종합 상태를 명시한다.
2. 충족한 항목은 근거 있는 새 모순·입력 오류가 발견될 때만 다시 연다. 점검 횟수가 늘었다는 이유로 전체를 재시작하지 않는다. 재개방 사유와 영향을 기록한다.
3. 위 기준을 충족하면 이 분석 보완 작업을 종료하고 첫 곡의 통합 제작안을 작성한다. 같은 목표 아래 새 필수 항목을 덧붙여 종료를 미루지 않는다. 생성 품질 비교는 별도 단계다.
4. 새 사용자 목표나 기준 자체의 명백한 오류 때문에 변경이 필요하면 변경 이유·영향·버전을 먼저 기록한다. 기존 v1.0 본문과 당시 판정은 보존하고 결과를 새 기준과 섞지 않는다. 결과를 통과시키려고 기준을 낮추거나, 새 문제를 이유로 조용히 강화하지 않는다.
5. 추가 분석 후에도 기술/자료 한계로 핵심을 구별하지 못하면 미완료를 정확히 보고하고 필요한 짧은 청취 확인 등 다음 행동을 특정한다. 모델을 무제한 교체·재질의하거나 원래 장비를 끝없이 역추적하지 않는다.

## 7. 기준의 출처와 적용 한계

- 프로젝트 목표·기록 원칙: 사용자 대화, `common/WORK_METHOD.md`, `archive_backup/claude-documents_2026-11-03/common/TEST_METHOD.md` (당시 참고 문서, 현재 필수 절차가 아님), 06~08 문서. 10개 항목·상태·완료 규칙은 AI가 이번 프로젝트에 맞춰 명문화한 운영 기준이다.
- [NIST: What are the objectives?](https://www.itl.nist.gov/div898/handbook/pri/section3/pri31.htm): 목표를 먼저 문서화하고 핵심 목적을 구분한다는 방법 원칙을 참고했다. NIST가 이 곡의 소리·10개 항목·합격선을 규정한다는 뜻은 아니다.
- [mir_eval transcription](https://mir-eval.readthedocs.io/latest/api/transcription.html), [onset](https://mir-eval.readthedocs.io/latest/api/onset.html): 음표/타격의 정답 비교는 참조 주석과 측정 조건을 필요로 한다. 라이브러리 기본 허용 창을 이 곡의 합격선으로 자동 채택하지 않았다.

이 문서 작성 턴의 실제 작업은 기존 기록·공식 방법 자료 확인, 기준 고정, 사후 초기 점검, 로컬 기록이다. 추가 음악 모델 설치·추론, 음원 가공, Suno 생성은 하지 않았다.
