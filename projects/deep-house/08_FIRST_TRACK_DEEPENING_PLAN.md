# 첫 곡 추가 정밀 분석 계획

2026-11-02. 사용자 질문: 최대한 완전한 재현을 목표로 할 때 추가 분석이 필요하지 않은가, 그렇다면 어떻게 진행할 것인가. 이 문서는 **추가 실행 전 계획**이다. 새 모델 설치·추가 추론·음원 가공은 이번 계획 작성에서 하지 않았다.

## 목표와 고정 범위

- 대상은 기존에 확인한 Lost in the Echoes의 0~222초뿐이다. 다른 곡·플레이리스트 전체로 확대하지 않는다.
- `07_LOST_IN_THE_ECHOES_ANALYSIS.md`에서 근거가 모인 약 105 BPM, Gb/Bb 중심 저음 골격, 중앙 저역/더 넓은 중역, 주요 편곡 변화는 유지한다. 이것을 처음부터 반복 측정하는 것이 아니라 세부 소리의 설명을 보완한다.
- 우선 해결할 질문은 네 가지: (1) 배경·전경 음색과 voice-like 성분은 어떤 소리인가, (2) 실제 음표 재발음과 주기적 진폭 변화는 어떻게 다른가, (3) 상층 음형·보이싱은 무엇이 반복되는가, (4) 공간의 폭·꼬리·전후 관계는 시간에 따라 어떻게 변하는가.
- 이 단계의 산출물은 보완 분석 보고서와 근거 구간 묶음이다. Suno 프롬프트 확정·생성으로 바로 넘어가지 않는다.

## 1. 추가 모델 실행 경로 확보

- Music Flamingo 공식 데모의 기존 3개 응답은 후보 설명으로 유지한다. 실패한 4번째 호출을 성공으로 세지 않고, 할당량 제한을 우회하지 않는다.
- 비교용 모델은 **Qwen/Qwen2-Audio-7B-Instruct의 오디오+텍스트 분석 모드**를 우선 선택한다. 모델 선정은 AI가 맡으며 사용자에게 선택을 넘기지 않는다.
- 로컬 별도 환경에서 4-bit 적재 가능성부터 확인한다. 현재 관찰: RTX 3060 12 GB, 가용 VRAM 약 6.9 GB, 기존 PyTorch는 CUDA 사용 가능. 이 관찰이 Qwen 실행 성공을 보장하지는 않는다. 기존 사용자 프로세스를 종료해 메모리를 확보하지 않는다.
- 짧은 구간 하나로 입력 길이·실제 GPU 메모리·처리 시간·응답을 확인한 후 확대한다. 메모리 문제가 있으면 CPU offload 경로를 한 차례 검토한다. 계속 실패하면 원인과 미실행 범위를 보고하고, 모델 답변이 존재한다고 꾸미지 않는다. 사용자 승인 없는 유료 외부 실행은 대안으로 자동 선택하지 않는다.
- Qwen과 Music Flamingo의 답이 같아도 정답을 입증한 것은 아니다. 다른 오디오 모델의 교차 설명과 신호 근거를 구분한다. 양자화도 설정에 기록한다.

공식 확인: [Qwen 모델 카드](https://huggingface.co/Qwen/Qwen2-Audio-7B-Instruct), [Transformers 구현](https://huggingface.co/docs/transformers/model_doc/qwen2_audio), [bitsandbytes 지원 환경](https://huggingface.co/docs/bitsandbytes/main/en/installation). 오디오+텍스트 분석과 Windows/NVIDIA 지원을 확인했으며 이 프로젝트에서의 실제 실행은 아직 하지 않았다.

## 2. 첫 곡의 핵심 장면과 소리 층 대응

| 구간 | 다룰 질문 |
|---|---|
| 0~18초 | 리듬·베이스에 가리지 않은 배경층의 어택·지속·음역·반복 형태 |
| 18~35초 | 저음 예고와 voice-like 전경 성분의 정체·시작/끝 |
| 39~72초 | 본문 드럼·베이스의 맞물림, 상층 반복의 최소 단위 |
| 92~104초 | 간헐적인 voice-like 배정 성분과 배경 신스의 차이 |
| 112~144초 | 배경층이 커졌을 때 음색·보이싱·폭의 변화 |
| 149~167초 | 저역이 빠진 상태의 배경 음형·꼬리, 국소 타격 |
| 188~200초 | 후반의 전경/voice-like 변화가 앞부분과 같은 종류인지 |
| 214~222초 | 악기 퇴장·잔류음·페이드·다음 곡 경계 전 마감 |

긴 장면은 모델 입력에서 약 15~30초로 나누고 필요하면 문맥을 겹친다. 원본·SW·Demucs에서 같은 시각을 대응시키며, 분리 아티팩트가 소리 정체처럼 보이는 경우는 보류한다. 전 곡의 사건 목록도 확인해 이 표 밖의 중요한 변화가 빠지지 않았는지 본다.

모델에는 처음에 제목·장르·예상 악기·기존 답을 숨긴다. 먼저 들리는 층과 시간 변화에 관한 자유 설명을 받고, 이후 구체적인 질문을 한다. 보컬이 반드시 있다는 전제를 넣지 않는다. 무음/아주 작은 스템을 크게 증폭한 결과를 원본의 전경 크기로 착각하지 않도록 원래 상대 음량을 같이 기록한다.

## 3. 음색·보이스 성분 조사

- 각 층을 악기 이름 하나로 끝내지 않고 **음역, 어택, 지속/감쇠, 밝기/배음, 변조, 반복 방식, 전경/배경 역할**로 기술한다.
- 신스 패드·플럭·키보드 계열·비언어 목소리 같은 후보는 모델의 설명, 원본 대응, 서로 다른 스템의 시간/주파수 성분으로 비교한다.
- vocals 스템의 간헐적 성분은 실제 사람 목소리, 보컬찹, 보이스 같은 합성음, 다른 소리의 혼입을 후보로 둔다. 해당 성분이 강한 구간과 약한 구간을 같은 질문으로 비교해 항상 보컬이라고 답하는 편향도 점검한다.
- 해결되면 층별 소리 명세와 출현 시각을 갱신한다. 해결되지 않으면 악기 정체와 소리의 특징을 구분해 기록한다. 정확한 프리셋 이름은 완료의 필수 조건으로 만들지 않는다.

## 4. 실제 음형·그루브 조사

- 대표 8마디에서 킥·중역 타격·고역 타격의 **공격점과 길이·강세**를 각각 기록한다. 기존 대역 에너지의 최대 시점은 공격점과 다르므로 그대로 미세 타이밍으로 쓰지 않는다.
- 베이스는 피치가 바뀌는 순간, 같은 음이 다시 시작되는 순간, 같은 음의 진폭만 줄었다 커지는 순간을 구분한다. 두 스템·원본 배음·포락선을 대조한다.
- Basic Pitch가 같은 지속음을 여러 이벤트/옥타브로 쪼갠 부분을 보정해, 음표 후보와 음량 운동을 분리한 도식을 만든다. 정답 MIDI가 없으므로 후보 MIDI를 원본 정답으로 선언하지 않는다.
- 상층은 한 음형/화음이 되풀이되는 길이, 음역·보이싱·리듬, 베이스 교대 때 유지/변경되는 음을 확인한다. 분리·전사·모델의 코드 이름만으로 진행을 확정하지 않는다.
- 도입·앞 본문·배경이 커진 본문·복귀 본문에서 반복 단위가 같은지 확인한다. 서로 다른 구간을 무조건 복사한 루프로 기록하지 않는다.

## 5. 공간감 조사

- 같은 소리가 비교적 노출된 도입·비움·마감과 본문을 대조한다. 직접적인 타격/발음과 이후 남는 소리의 관계를 조사한다.
- 대역별 Mid/Side뿐 아니라 시간에 따른 좌우 레벨 차이·상관·반복되는 꼬리/에코 간격을 본다. 스테레오 폭을 곧바로 리버브 양으로 환산하지 않는다.
- 원음 릴리즈, 반복 에코, 확산된 잔향, 전체 페이드가 구분 가능한지 확인한다. 구분이 안 되면 시간 곡선은 제시하되 플러그인·RT60·wet %로 이름 붙이지 않는다.
- 결과는 ‘저역을 얼마나 안정적으로 중앙에 둘지’, ‘어떤 배경층에 폭과 꼬리가 있는지’, ‘얼마나 오래 공간을 채우는지’를 설명하는 명세로 만든다. 원래 노브 값을 찾는 일을 필수 목표로 두지 않는다.

## 6. 재검토와 제출 조건

다음 항목을 갖춘 보완 보고서를 제출한다.

1. 주요 소리 층별 명세와 근거 시각. 분석한 레이어·의미 있는 이벤트가 빠지지 않았는지 전체 첫 곡 시간표와 대응.
2. 대표 반복의 드럼 공격점/길이/강세, 베이스의 음표·포락선, 상층 보이싱·음형 후보.
3. 도입·본문·비움·복귀·마감에서 무엇이 유지되고 변하는지 비교.
4. 공간의 폭·지속·전후 관계와, 사용 기법을 특정할 수 없는 부분의 구분.
5. 주장별로 모델 설명·측정·음악적 해석·사용자 청취 확인·미확인을 표시. 기존 07 보고서에서 유지·수정·철회한 주장과 근거.

서로 다른 모델의 유창한 설명 일치만으로 항목을 통과시키지 않는다. 추가 측정 후에도 중요한 음색 정체가 갈리면, 해당 **짧은 원본 구간과 비교 스템만** 사용자에게 제시하고 필요한 청감 차이를 묻는다. 기술 도구 선택이나 장문의 전곡 라벨링을 사용자에게 넘기지 않는다. 청취 평가를 받기 전에는 받은 것으로 기록하지 않는다.

분석을 끝내는 판정은 후속 문서 `09_FIRST_TRACK_ANALYSIS_CRITERIA_V1.md`에 고정한 10개 항목·상태·완료/변경 규칙을 따른다. 핵심을 막는 불확실성을 미확인으로 적는 것만으로 통과시키지 않는다. 기존 목표와 기준을 유지하며 미완료 항목을 해결한 뒤 통합 프롬프트와 생성·선곡 비교 계획을 작성한다.
