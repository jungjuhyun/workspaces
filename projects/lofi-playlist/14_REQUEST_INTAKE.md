# 음악 의뢰 접수와 방향 확정 절차

문서 묶음0.10.0 / 접수 절차1.0 / 2026-10-27 (Asia/Seoul)
담당 범위: 의뢰를 받아 다음 조사·설계 작업에 넘기는 앞단. 현재 P5의 앞단 보완이며 P5 전체의 완료 선언이 아니다.

## 1. 이 절차의 목적과 적용 범위

먼저 사용자가 무엇을 만들고 싶은지 파악한다. 정해진 목표는 보존하고, 정해지지 않은 부분은 AI가 탐색을 도와 좁힌다. 사용자가 음악 용어·장르·악기·BPM·코드를 미리 결정해야 시작할 수 있는 절차가 아니다.

공통으로 재사용하는 것은 접수·탐색·합의·인계·변경·기록 방법이다. 음악의 내용은 의뢰별 프로필로 관리한다. 현재 lo-fi의 목표 청감·무보컬·20곡·건반 노출·v6-mini 우선·원본 Exclude를 새 의뢰의 기본값으로 이식하지 않는다. 02/06의 T·D 음악 판정과12의 OPT는 현재 lo-fi 프로필에 적용하며 모든 장르의 공통 음악 기준이 아니다.

사용자의 최신 유효 지시와 기존 허용 범위가 우선한다. 이 문서를 읽거나 예시를 실행했다는 사실이 새 작업·생성·비용 사용 허가가 되지는 않는다. 반대로 이미 허용된 조사·설계 하위 작업마다 다시 허락을 받지도 않는다.

## 2. 시작할 때 두 가지를 따로 판단한다

AI는 현재 메시지와 기존 파일을 먼저 읽고 아래 두 축을 기록한다. 분명한 내용은 사용자에게 선택지를 다시 묻지 않는다.

| 축 | 분류 | 처리 |
|---|---|---|
| 기존 작업과의 관계 | 이어가기 | 기존 목표·선택·미해결·다음 행동을 불러오고 변경점만 반영 |
| 기존 작업과의 관계 | 기존 작업 변경 | 무엇을 유지/교체하는지 확인하고 영향받는 기준·설계만 개정 |
| 기존 작업과의 관계 | 새 의뢰 | 새 요청 ID/프로필로 시작. 기존 작업은 보존하며 필요한 방법·자료만 적용 범위를 판단해 재사용 |
| 방향의 구체성 | 명확 | 알려진 목표를 요구로 정리하고 중요한 누락/충돌만 확인 |
| 방향의 구체성 | 일부만 있음 | 주제·장면·가사·리듬·참고곡·악기 등 이미 있는 단서를 고정하고 나머지만 탐색 |
| 방향의 구체성 | 미정 | 사용 목적이나 끌리는/싫은 경험부터 탐색. 장르 선택부터 강요하지 않음 |

예를 들어 '다음에는 보컬이 있는 곡을 만들고 싶다'는 새 의뢰일 수도 있고 기존 프로필 변경일 수도 있다. 맥락으로 구분되지 않고 결과가 달라질 때만 둘 중 무엇인지 짧게 묻는다. 새 의뢰이면서 방향이 명확할 수 있고, 이어가는 작업인데 일부 방향만 바뀔 수도 있다.

프로젝트 연결을 확인할 때는00과05 및 상태 JSON의 정본 ID를 사용한다. 새 채팅이 자동으로 파일을 읽는다고 가정하지 않는다. 기록을 찾지 못했으면 찾지 못한 항목만 밝히고 필요한 핵심만 확인한다.

## 3. 사용자의 말을 작업 가능한 요구로 정리한다

한 번에 설문지 전체를 채우게 하지 않는다. 아래는 AI의 확인 목록이며 모든 칸이 필수 입력은 아니다.

| 확인할 내용 | 쉬운 질문/확인 예 | 미정일 때 처리 |
|---|---|---|
| 목적·상황·청자 | 어디에서 어떤 때 쓰거나 듣는 음악인가? | 목적이 없다면 좋아하는 경험/만들고 싶은 이유로 탐색 가능 |
| 만들고 싶은 것·현재 단서 | 곡·연주곡·노래·플레이리스트·영상용 중 무엇인가? 이미 떠오른 장면/가사/소리가 있는가? | 산출물 차이가 다음 결정을 바꿀 때만 질문 |
| 원하는 경험 | 듣는 동안 무엇이 느껴지거나 어떤 역할을 하면 좋은가? | 감정 단어·비유를 허용하고 AI가 해석 후보를 제시 |
| 피할 것 | 절대 넣고 싶지 않은 소리나 싫었던 결과가 있는가? | 언급이 없다는 이유로 기존 프로젝트의 금지사항을 가져오지 않음 |
| 참고 자료 | 곡·구간·영상·이미지 중 어떤 부분이 좋은가? | 참고곡이 없어도 시작. AI가 찾아줄 수 있음 |
| 범위·실무 조건 | 이번에는 방향 탐색/설계/프롬프트/제작 중 어디까지 필요한가? 분량·기한·도구 조건은 있는가? | 현재 작업에 필요한 조건만 확인. 실제 실행 비용/한도는 실행 직전 별도 확정 |
| 선택·위임 | 중요한 방향은 직접 고를 것인가, 조건 안에서 AI가 고를 것인가? | 이미 선택/위임했다면 재확인 없음. 결과를 바꾸는 선택 공백만 질문 |

핵심 공백·충돌만 한 번에1~3개의 쉬운 질문으로 묻는 것을 기본 운영 방식으로 삼는다. 이 숫자는 음악적 합격 기준이 아니다. 답변이 없으면 이미 확인된 자료 정리·독립 조사 등은 계속하되, 사용자 선택이 꼭 필요한 방향을 임의로 확정하지 않는다. 선택을 위임받았다면 그 범위 안에서 이유와 가정을 기록하고 진행한다.

사용자 원문과 AI 해석은 구분한다. 예를 들어 '밤에 듣는 따뜻한 곡'을 '무조건 느리고 어두운 무보컬 lo-fi'로 자동 변환하지 않는다. '웅장하지만 배경에 놓였으면' 같은 요구도 즉시 모순으로 판정하지 않고, 어느 구간·역할·정도가 중요한지 확인한다. 실제로 양립할 수 없거나 제품상 불가능한 조건만 영향과 대안을 설명한다.

## 4. 방향이 없거나 일부만 있을 때의 탐색

1. 이미 정해진 목적·단서·싫은 요소를 보존한다. 탐색할 미정 영역과 이번에 결정할 질문을 한 문장으로 정한다.
2. 그 질문에 맞춰 웹 조사와 기존 자료 조회를 한다. 음악 원리/제품 사실은 일차 자료를 우선하고 사례는 공개 조건·반례·적용 범위를 기록한다. 검색량이나 최신 유행 자체를 사용자의 취향으로 간주하지 않는다.
3. 초기에는 보통2~3개의 구별되는 방향을 같은 항목으로 비교한다. 수는 작업상 제안이며 의무 수량이 아니다. 각 방향에 사용 장면·핵심 소리/움직임·보컬/가사 필요성·전개·장점/위험·맞는 이유를 적는다. 악기 이름·제목·장르명만 바꾼 선택지를 내지 않는다.
4. 참고 자료가 도움되면 곡/구간과 '참고할 요소/따르지 않을 요소'를 함께 제시한다. 페이지/곡명 확인, 사용자의 감상, AI의 직접 오디오 확인을 구분한다. 소리를 확인하지 못한 경우 들은 것처럼 분석하지 않고, 사용자 설명을 근거로 한 범위를 표시하거나 접근 가능한 자료로 대체한다.
5. 사용자는 하나 선택, 특정 요소 조합, 모두 거절, 추가 탐색, AI 위임 중 편한 방식으로 반응할 수 있다. 전부 싫다면 새 후보를 무작정 늘리기 전에 공통으로 싫은 점을 짚어 탐색 축을 바꾼다.
6. 다음 제작 결정을 할 정도로 방향이 좁혀지면 탐색을 닫고 의뢰 요약으로 넘긴다. 미정이면 NEEDS_DIRECTION으로 남겨 다음 질문을 명시한다. 확정 전제의 프롬프트/대량 곡 설계로 건너뛰지 않는다.

자료 비교로도 구분이 어려워 실제 소리 비교가 필요한 경우, 먼저 비교할 질문과 후보 입력을 설계할 수 있다. 실제 생성은 실행 허용·비용/계정 조건을 충족한 별도 실행으로 처리한다. 방향을 찾기 위해 실험을 설계할 수 있다는 이유로 임의 생성하지 않는다.

선택 횟수 자체로 완료하지 않는다. 반대로 '더 좋은 방향이 있을지도 모른다'는 이유로 선택된 방향을 계속 다시 열지도 않는다. 다시 탐색하는 이유는 새 지시·중요한 충돌·확인된 실패·판단을 바꾸는 새 근거로 한정하고 해당 부분만 수정한다.

## 5. 의뢰 요약과 기록 양식

접수 결과는 하나의 의뢰 요약으로 정리한다. 같은 사실을 여러 문서에서 별도로 관리하지 않고, 기존 프로젝트라면 정본과 해당 ID/버전을 연결한다. 새 의뢰는 독립 프로필을 만들고 원래 프로젝트의 기준과 기록을 덮어쓰지 않는다. 실제 새 의뢰가 생기면 그 요청 ID의 프로필 파일을 저장하고 진행 기록에 파일 ID·이름·현재 버전을 연결한다. 공통 절차 문서를 개별 의뢰의 결과로 덮어쓰지 않는다.

```text
request_id / project_id / brief_version / updated_at
관계: 이어가기 | 변경 | 새 의뢰
구체성: 명확 | 일부 | 미정
현재 할 일: 탐색 | 조사 | 설계 | 입력 작성 | 실행 | 검토
사용자 원문·출처:
만들 것·사용 목적·원하는 경험:
지킬 단서:
요구 항목: local_id, 내용, 필수/선호/미정, 근거·출처, 상태, 확인 방법
  상태: USER_FIXED | USER_PREFERENCE | AI_PROPOSED | OPEN | SUPERSEDED
참고: 자료/구간, 참고할 요소, 따르지 않을 요소, 실제 확인 수준
AI 해석/제안과 선택 이유:
선택/위임: 대상·범위·근거 발언; 승인받지 않은 제안은 명시
충돌/공백: 영향받는 결정, 해결 방법, 지금 독립 진행할 일
범위·산출물·현재 허용:
이번 작업의 완료 조건:
현재 단계: NEEDS_DIRECTION | READY_FOR_RESEARCH | READY_FOR_DESIGN | PAUSED
다음 한 가지 행동 / 담당 / 재개에 필요한 입력:
연결 정본·설계·출처·이력:
변경 이력: 이전 버전, 요청 원문, 유지/교체 항목, 영향받는 작업/결정
```

필수/선호는 중요도이고 상태는 그 조건을 누가 정했는지·유효한지다. 서로 다른 정보이므로 한 라벨로 섞지 않는다. AI가 제안한 필수 조건도 채택/위임 근거가 없으면 사용자 확정 조건으로 승격하지 않는다. 사용자 표현이 애매하면 AI의 해석과 확인할 지점을 나란히 기록한다.

음악 판단 기준은 사용자가 원하는 경험을 확인할 수 있는 관찰로 연결한다. 예: '말소리를 방해하지 않는 배경 음악'은 보컬 유무·전면 선율/타악의 주의 끌림·실제 사용 환경의 방해 여부 등으로 풀되, 사용자가 정하지 않은 수치·금지·장르를 강제로 만들지 않는다. 새 의뢰는 그 목적에 맞는 기준을 조사해 정하고, 이미 정해진 현재 lo-fi는02/06을 그대로 참조한다.

AI가 작성하고 대조·검수·기록한다. 사용자는 AI만으로 확인할 수 없는 취향/핵심 사실을 알려주거나 중요한 선택을 한다. 이미 명확한 요구·위임·진행 지시를 다시 '승인해 달라'고 돌려보내지 않는다. AI 해석이 목표를 실질적으로 바꾸거나 필수 조건끼리 충돌하는 경우에만 그 쟁점을 구체적으로 확인한다.

## 6. 다음 단계로 넘어가는 조건

아래는 접수의 단계별 인계 조건이다. 기존 G01~G10이나 음악 합격 기준의 대체 번호가 아니다.

| 현재 상태/도착점 | 필요한 조건 | 아직 없어도 되는 것 |
|---|---|---|
| NEEDS_DIRECTION → 방향 탐색 | 원하는 단서 또는 탐색 질문, 기존 요구/금지, 이번 탐색 범위가 식별됨 | 장르·참고곡·BPM·악기·코드의 사전 확정 |
| READY_FOR_RESEARCH → 조사 | 무엇을 알아봐야 하며 어떤 선택에 쓸지, 자료를 고를 기준과 기록 위치, 허용 범위가 정해짐 | 조사로 결정할 음악 세부값. 아직 미정인 값은 미정으로 유지 |
| READY_FOR_DESIGN → 곡/묶음 설계 | 만들 것·핵심 방향·필수/피할 것·조정 가능 범위·이번 완료 조건과 중요한 선택/위임이 식별되고, 설계를 바꾸는 충돌이 해소됨 | 모든 악기/음표/코드/계정 옵션의 확정. 사소한 미정은 위임/가정·영향을 기록해 진행 |
| 입력 작성 → 실제 생성 | 완결 입력·실제 도구/계정 제약·참조·기록/평가 계획과 실행 허용/비용 범위 | 현재 lo-fi는13 COMMIT-GATE 적용. 다른 프로젝트는 해당 도구·목표에 맞는 실행 조건 연결 |

READY_FOR_RESEARCH와 READY_FOR_DESIGN은 해당 다음 작업에 준비됐다는 뜻이다. 좋은 음악을 이미 완성했거나 청감 검증을 통과했다는 뜻이 아니다. 방향을 정하기 위한 조사와 방향이 정해진 뒤의 세부 조사를 구분하므로 '기준을 조사하려면 모든 음악 기준이 완성되어야 한다'는 순환을 만들지 않는다.

기존 프로젝트는 해당 입력/근거가 계속 유효한 범위에서 이어간다. 현재 lo-fi의 P1~P4 전체를 접수 절차가 새로 생겼다는 이유로 재시작하지 않는다. 미확인 값이 막는 결정만 보류한다. 현재 P5 후속은12/13을 사용하는 선택·조합·유사곡 조회·충돌/중복 판정·기록/수정 절차다. 그 절차가 끝나면 P6의 첫 제작분·통합 입력으로 넘긴다.

## 7. 새 아이디어·변경·재개 처리

- 새 아이디어는 우선 원문과 의도한 범위를 남긴다. 기존 목표를 유지한 변형이면 해당 의뢰의 새 버전, 별개 작품이면 새 의뢰/프로필이다. 둘의 구분이 결과를 바꿀 때만 확인한다.
- 목표가 바뀌면 바뀐 항목을 SUPERSEDED로 이력에 남기고 새 조건을 연결한다. 최신 지시가 우선하는 범위만 적용하며, 출처 사실·다른 곡·기존 파일 전체를 무효화하지 않는다.
- 기준 변경은 영향받는 설계·입력·비교 판단을 표시한다. 예를 들어 새 보컬 곡에 무보컬 기준을 강요하지 않으며, 그 요청만으로 기존 lo-fi 연주곡 기준을 폐기하지 않는다.
- 작업 재개 시 AI가 의뢰 요약·최신 결정·미해결·다음 행동을 읽어 현재 상태를 짧게 알리고 이어간다. 매번 사용 목적부터 다시 묻지 않는다. 실제로 달라질 수 있는 제품/계정 정보는 해당 실행 직전에 재확인한다.
- 선택/답변 대기 중에는 해당 선택에 의존하는 확정 작업만 보류한다. 명시적 중단이면 중단 범위를 적용한다. 무응답을 승인으로 바꾸지 않는다.

## 10. 이번 제출 기준과 근거

문서 편집 전에 다음8개 항목을 고정했다. 중요 결함이 없고 이 항목을 충족하면 접수 절차 작성은 종료한다. 다음 의뢰의 내용은 개별 프로필에서 정하며 공통 절차 문서를 매번 다시 만드는 이유로 삼지 않는다.

1. 기존 작업과의 관계와 방향의 구체성을 별도로 판단한다.
2. 기존 자료를 먼저 읽고 중요한 공백·충돌만 쉬운 질문으로 확인한다.
3. 부분 아이디어를 보존하고 탐색의 비교·반응·수렴·미응답 분기를 갖춘다.
4. 원문·AI 해석/제안·선택/위임·미정과 공통 절차/프로필을 분리한다.
5. 의뢰 요약에 필수/선호·관찰 방법·참조 범위·산출·다음 행동을 연결한다.
6. 조사·설계·생성의 진입 조건을 분리하고 기존 연구의 불필요한 재시작을 막는다.
7. 변경 영향과 이력을 보존하고 새 의뢰에 기존 음악 기준을 자동 이식하지 않는다.
8. 현재 사례와 가상 분기를 대조하고 기존 기준 보존·검증·저장을 확인한다.
