# 근거 통합과 비교 시험 계획

문서 묶음0.9.0 / 2026-10-27 / P4 / 기존 R01~R22·T01~T08·E/D/G 적용

## 이번에 정한 진행 방향

**기본 첫 비교는 TST-02A, 건반의 시작 발음 명시다. 기본 모델은 v6-mini이며 신규 생성 경로를 우선 검토한다.** 모델·악기·음역/음형·기타 조건의 입력 의도는 유지하고 발음 설명만 바꾼다. 다음 기본 순서는 음역(TST-01), 반복/쉼(TST-03)이다. 실제 출력에서 다른 문제가 먼저 확인되면 해당 계획을 앞당긴 이유를 기록한다. 이 순서는 원인 진단이나 효과 확정이 아니라 초기 우선순위다.

11의 사례·12의 음악 선택지를 핵심 판단11개에 연결하고, 개별 비교/확인14개와 조건부 상호작용 계획1개를 만들었다. 모든 계획을 한꺼번에 실행하는 목록이 아니다. 한 비교를 정해 사전 입력·비용·기록을 확정하고 결과에 따라 다음 질문으로 넘어간다.

이 문서는 비교 설계의 정본이다. 출처·검색·주장/계획 ID 원장은03, 음악 기준은02, 판정 규칙은06, 실제 시도/결과는04가 담당한다. 09의 원본 입력과11/12의 제출 문서는 변경하지 않는다. 이번 기록의 계획 ID는 EXP나 실제 출력 ID가 아니다.

## 비교 방법을 정한 근거

NIST의 블록/무작위화·한 요인 비교의 한계·요인 교차 설계를 확인했다. 그 원리를 바탕으로 비교 순서·회차를 남기고, 단일 입력 변경에서 나온 좋은 값을 무조건 합치지 않는다. 필요한 경우에만 INT-01의 두 요인 교차 확인을 검토한다. [SRC-0079~0081]

ITU-R BS.1534-3의 현재 공식 목록과 원문을 확인했다. 음량과 비교 조건을 정렬하는 원리만 참고한다. 서로 다른 곡이 생성되는 이 계획을 reference/anchor 기반 MUSHRA 시험이나 표준 준수 시험으로 부르지 않는다. [SRC-0082]

MusicGen 원저의 품질/텍스트 관련성 구분을 참고해, '지시 반영'과 '우리 목표 적합'을 나눈다. 논문의 점수·음량 수치·평가자 수/제외 규칙을 복사하지 않는다. 기존 T01~T08·D조건이 평가의 정본이다. [SRC-0083]

여기서 정한 회차·요청 수는 **이 프로젝트의 초기 시험 설계 제안**이다. 위 출처가 Suno에서 그 수면 충분하다고 정해 준 것이 아니며 음악의 합격 기준도 아니다.

## 비교 전에 구별하는 네 가지

| 이름 | 의미 | 혼동하지 않을 것 |
|---|---|---|
| 기준 입력 BASE | 한 비교의 A/B를 만들 공통 음악 설계·전체 입력/설정의 버전 | 회수 원본은 보존 입력이다. 당시 실제 모델/설정을 아는 완전 재현 조건이라고 부르지 않음 |
| 대조 A | 해당 비교의 기준 조건 | 항상 회수 원본과 글자까지 같은 입력인 것은 아님. 시험용 변형이면 그 버전을 명시 |
| 목표 기준 음원 | 사용자가 승인한 목표 소리·구간 | 실험의 A·과거 출력·공유 링크라는 이유로 승인 기준으로 간주하지 않음 |
| 생성 참조 오디오 | Cover/Extend 등의 실제 투입 파일·구간 | 목표 기준 음원과 같다고 가정하지 않음. 사용한 경로·구간·옵션을 별도로 기록 |

입력에서 한 항목만 바꿔도 실제 출력에서는 음량·음형·편성·길이 등이 함께 바뀔 수 있다. **단일 입력 대비는 그 요청을 바꾼 결과의 비교**이며, 나머지 음악이 물리적으로 똑같이 고정된 실험은 아니다. 패키지 비교는 구성·리듬·역할의 묶음 차이로 보고 원인 하나를 골라 말하지 않는다.

| 계정/경로 | 정확한 모델 표시·버전/시각, 생성 방식, 실제 제공 옵션/현재값·범위, 길이/개인화/보강, 참조 파일·구간 | 제공되지 않거나 미확인인 설정만 잠금. 값·시드·한도를 지어내지 않음 |

| 실행/비용 | 유효한 생성 허용 범위, 최대 요청 수·실제 요금/크레딧, 예상 합계·넘길 수 없는 상한 | 가격·배수·무료 여부를 추정해 시작하지 않음. 이미 허용된 하위 행동마다 재승인 요구 안 함 |

목표 기준 음원 부족은 D05/D07의 긍정 판정을 잠근다. 그것을 이유로 자료 분석·문구/설계 검토·기록 등 독립된 작업을 전부 중단하지 않는다. 사용자의 실제 불편 보고나 명시적 금지 위반은 기준 음원 유무와 별개로 그 범위에 기록한다. 현재 지원 여부가 확인되지 않은 기능은 시험에 억지로 포함하지 않는다.

## 전체 결과를 남기는 비교 절차

1. **대비를 하나 고른다.** 기본은 TST-02A다. 해당 테스트의 전체 입력·고정 조건·관찰·상한을 위 명세로 확정하고 BASE 버전을 잠근다. 이전 비교에서 채택한 변경을 반영하려면 새 BASE로 명시하며, 과거 대비를 같은 조건의 반복으로 합치지 않는다.
2. **생성 순서와 재생 순서를 따로 정한다.** 두 조건의 본 비교는 A선행2회/B선행2회가 되도록 회차 순서를 사전에 섞어 고정한다. 재생용 익명 ID의 순서는 별도로 정한다. 실제로 조건을 알고 들었다면 가림 평가라고 보고하지 않는다. 이 순서 무작위화는 Suno의 생성 시드를 통제했다는 뜻이 아니다.
3. **먼저 구현 확인을 한다.** A/B 차이 유무와 각 조건의 요청 충족은 별개다. A/B가 모두 이미 둥근 발음일 수 있으므로 차이 없음만으로 미반영 판정하지 않는다. 예비 A/B 각1요청에서 지시의 차이가 관찰 가능한지와 기록/입력 문제가 없는지 본다. 지시가 안 먹은 출력은 버리지 않고 미반영 결과로 남긴다. 미반영과 통신/잘못된 설정 같은 절차 오류를 구분한다.
4. **본 비교는 사전에 고정한4회차로 제안한다.** 한 회차에서 조건별1요청을 수행하고, 매 요청에서 실제 반환된 정식 출력 모두를 기록한다. 예비 출력은 본 비교와 별도 표로 둔다. 예비가 그럴듯했다는 이유로 본 비교를 생략해 효과를 확정하지 않는다.
5. **요청과 출력 수를 구분한다.** 한 요청이 두 곡을 반환해도 독립 반복2회로 세지 않는다. 잠긴 preview·중복 ID·오류/누락을 구분하고, 조건별 반환 수가 달랐다는 사실도 남긴다. '좋은 한 곡'만 비교하지 않으며 요청/회차 안의 결과 분포를 요약한다.
6. **지시 반영과 목표 적합을 따로 본다.** 의도한 차이의 반영/부분 반영/미반영/미판정과 T01~T08 관찰을 분리한다. 입력 의도에서 고정한 음악이 실제로 달라졌으면 동반 변화로 표시한다. 미반영 출력을 사후 삭제해 성공률을 높이지 않는다.
7. **같은 재생 조건과 관찰 단위를 기록한다.** 원본을 보존하고 비교용 파일은 원본과 연결한다. 음량을 맞춘 경우 전체 신호의 gain·방법을 남기며 EQ/컴프레서/노이즈 제거로 시험 내용을 바꾸지 않는다. 음량·상대 배치·반복 노출 자체가 질문이면 원래 재생 조건의 관찰도 따로 남겨 효과를 지워 버리지 않는다.
8. **전체 흐름과 기능이 같은 구간을 함께 본다.** 도입·안정 구간·후반·문제 구간은 실제 위치로 기록하고, 마음에 드는 짧은 구간만 고르지 않는다. 길이가 다르면 같은 초가 같은 음악 기능이라는 가정 없이 구간을 대응한다. 음량·고역·템포 등의 측정은 보조 관찰로 쓰며 단일 수치가 T판정을 대신하지 않는다.
9. **계획대로 요약하고 멈춘다.** 조건별 총 요청/반환·절차 오류·지시 미반영·목표 위반·보류를 모두 표시한다. 작은 표본의 경향·상반 결과를 숨기거나 자동으로 모집단 순위/인과 법칙으로 바꾸지 않는다. 동률·엇갈림도 정상 결론이다.

### 요청 수와 중단의 상한

- 첫 두 조건 비교의 초기 제안은 예비2요청 + 본 비교8요청 = 최대10요청이다. 이는 비용을 제한한 탐색 설계이며 통계적 충분성/음악 합격의 숫자가 아니다. 실제 허용 상한이 더 낮으면 시작 전에 계획을 다시 고정하거나 보류한다.
- 그 범위에는 실제 요청한 오류/잘못된 설정의 시도도 기록한다. 청구/환불은 플랫폼의 실제 결과로 구분한다. 빠진 유효 회차를 메우려고 상한 밖의 재생성을 자동 실행하지 않는다.
- TST-10을 세 모델로 비교한다면 별도 제안은 예비1회차×3요청 + 본 비교6회차×3요청 =21요청이다. 본 비교에서 세 조건의 순서를 균형 있게 배치한다. 초기 기본 비교에 포함하지 않고 필요·비용을 확인한 경우에만 검토한다.
- INT-01은 예비 네 셀1회차4요청 + 본 비교 네 셀4회차16요청 =20요청의 조건부 제안이다. 각 셀이 순서 위치에 고르게 오도록 표를 고정한다. 모든 요인 조합을 무작정 늘리지 않는다.
- TST-11E/R은 실제 문제가 있는 원본과 한 경로부터 별도 견적을 정한다. 같은 문제 출력에 두 경로를 연이어 섞지 않는다. TST-12는 확보된 곡의 검토이며 이를 위해 새 곡을 무조건 생성하지 않는다.
- 예비에서 입력/기능/기록이 작동하지 않으면 해당 대비를 멈춰 원인을 수정한다. 명시적 목표 위반·불편 보고로 중단했다면 실제 관찰과 중단 범위를 기록하고 그 출력/구간의 판단으로 제한한다.
- 정한 회차가 끝나면 유지/후속 후보/수정/보류 중 하나로 정리한다. 결과가 마음에 들 때까지 다시 뽑지 않는다. 추가 비교는 새 근거·구체적 미해결 질문과 허용 상한을 명시한 새 계획 버전으로만 다룬다.

## 무엇을 보고 어떤 결정을 내리는가

기존 T01~T08의 의미·허용 기준은06을 따른다. 아래는 그 기준을 기록으로 옮기는 순서다.

| 기록 단계 | 내용 | 다음 결정 |
|---|---|---|
| 절차 유효성 | 실제 모델/설정/입력·파일 연결·반환 누락·승인 상한 준수 | 절차 오류는 INVALID_PROTOCOL로 남기고 영향받는 비교는 보류. 실패 요청/비용은 지우지 않음 |
| 지시 반영 | 의도한 음악 차이와 동반 변화, 실제 확인 구간 | 지시 미반영은 IMPLEMENTATION_FAILURE/PARTIAL로 남김. 절차 오류로 바꿔 분석에서 삭제하지 않음 |
| 대비 성립 | 의도한 요인의 A/B 차이가 실제 관찰되는지, 둘 다 요청을 이미 충족했는지 | 차이 없음/미판정은 CONTRAST_UNRESOLVED로 별도 기록. 요청 미반영이나 물리적 효과 없음의 증명으로 바꾸지 않음 |
| 명시적 목표 위반 | 보컬/잡음·과한 드럼/상승·둥글지 않은 발음·저음 가림·사용자 불편 등 해당 T | 해당 출력/구간 수정 또는 제외. 다른 장점의 합산 점수로 필수 위반을 상쇄하지 않음 |
| 목표 적합 | 동일한 기준과 재생 조건에서 T01~T05/T07 및 해당 T08 관찰 | 요건이 갖춰진 범위에서 D05 판정. 충분한 입력이 없으면 판단 범위를 유지하고 HOLD |
| 지속되는 구별 | 가장 유사한 곡과 도입·본문의 음형/그루브/화성/역할 차이, 실제 구간 | D06 적용. 인트로만 달라진 대조는 충분한 구별 근거로 채택하지 않음 |
| 반복/일반화 | 회차별 방향·실패·예외·다른 음악 맥락에서의 재확인 | 후보를 다른 합당한 편성/밀도 맥락으로 옮길 때는 새 BASE를 쓰고 그 맥락 안에서 같은 대비를 반복. 단순히 좋은 값들을 합쳐 프리셋으로 확정하지 않음 |
| 보류/개별 선택 | 같은 목표 안의 장단점·혼합 결과·사용자의 실제 선택/위임 범위 | 보류·조건부 후보·개별 채택을 분리. 한 곡 채택을 D07 프리셋 승인으로 바꾸지 않음 |

판정 라벨은 MAINTAIN_BASE / NEXT_CANDIDATE / REVISE / HOLD로 요약하되 실제 T/D 근거와 범위를 붙인다. 이는 새로운 음악 점수표가 아니다. 어느 변형이 상대적으로 좋았다는 이유만으로 필수 목표를 충족했다고 하지 않는다.

### TST-01 — 건반 음역 지시

- 바꿀 것: 음역 추가 지시 유무
- A: 공통 입력의 건반에 별도 음역 지시 없음
- B/다른 조건: 건반의 중간·중저역 배치를 추가 명시
- 고정할 입력·환경: 모델/방식·악기·어택/밝기 의도·음형/밀도·화성·저음·타악·Exclude·옵션·참조
- 관찰과 평가: 실제 음역 변화와 동시에 변한 발음/배치, T01/T02/T08을 구분
- 실패/중단·해석 한계: 음역이 같으면 그 사실을 기록. 높은 음 존재만으로 탈락하거나 음역 지시의 무효를 일반화하지 않음
- 연결: P4-C03, P4-C10 / OPT-I01, OPT-I02, OPT-H03

### TST-02A — 건반 발음 명시

- 바꿀 것: 건반 시작 발음의 추가 명시
- A: 공통 기본 입력의 발음 설명 유지
- B/다른 조건: 음역·배음 의도는 유지하고 둥근 시작 발음만 추가 명시
- 고정할 입력·환경: 모델/방식·건반/음역·반복/쉼·배음 의도·화성·저음·타악·Exclude·옵션·참조
- 관찰과 평가: 실제 시작 발음 변화, 소리 크기/배음/음역의 동반 변화, 음 구별·T01/T02/T08
- 실패/중단·해석 한계: 너무 흐려 음 구별이 무너지거나 더 전면으로 튀면 수정 후보. A/B 차이가 없다는 사실과 요청 미반영을 구분한다. 둘 다 이미 둥근 발음일 수 있으며 요청을 충족하지 못했을 때만 미반영으로 기록.
- 연결: P4-C02, P4-C03, P4-C06, P4-C10 / OPT-I01, OPT-I02

### TST-02B — 건반 배음·밝기 명시

- 바꿀 것: 음색의 밝은 울림 억제 명시
- A: 공통 기본 입력의 어두운 음색 의도 유지
- B/다른 조건: 발음/음역/밀도 의도는 유지하고 밝은 울림 억제를 추가 명시

- 연결: P4-C02, P4-C03, P4-C10 / OPT-I02, OPT-I08

- 연결: P4-C03, P4-C05, P4-C11, P4-C10 / OPT-M01, OPT-M02, OPT-F04

### TST-07 — 악기 간 응답 관계

- 바꿀 것: 같은 편성의 주역/응답 관계
- A: 주된 악기가 구절을 맡고 다른 악기는 지지

### TST-12 — 건반 누적 노출과 곡 순서

- 바꿀 것: 실제 선택한 곡들의 노출/순서 검토
- A: 선택한 목표 길이 구성의 개별 곡과 원래 순서
- B/다른 조건: 필요시 같은 곡 집합의 순서만 바꾼 후보를 별도 회차에 검토
- 고정할 입력·환경: 곡/파일 집합·가능한 같은 재생 환경/음량·실제 노출 시간·평가자·회차 조건
- 관찰과 평가: 건반 음역/발음/반복의 누적, 거슬림·주의 끌림·지루함을 구분하고 곡/구간·발생 시간을 기록

### INT-01 — 음역×발음의 상호작용

- 바꿀 것: 음역 지시와 발음 지시의 2×2 조합
- A: 각 요인의 두 상태를 교차한 네 입력 셀
- B/다른 조건: 별도의 A/B 승자 선택 대신 네 셀의 관계를 비교
- 고정할 입력·환경: 두 요인 외 BASE/입력·모델/방식·옵션·참조·평가 방법을 고정
- 관찰과 평가: 한 발음 지시의 방향이 음역 조건에 따라 바뀌는지, T01/T02/T08과 동반 변화
- 실패/중단·해석 한계: 한 요인씩의 결과를 더해 최적 조합이라 단정하지 않음. 목표 밖의 불쾌한 극단값을 만들지 않음. 비용 확인 후 조건부 실행
- 연결: P4-C02, P4-C03 / OPT-I01, OPT-I02, OPT-H03

## TST-12의 누적 확인 기록

목표1시간은 사용자 요구의 맥락이다. 미리 정해 둔 고역/옥타브/반복 수 임계값을 새로 만들지 않는다. 선택한 곡·순서, 실제 청취한 시간, 재생 환경/음량, 쉬거나 바꾼 조건, 문제 곡·구간과 표현을 기록한다. 거슬림·지루함·주의를 끄는 느낌을 섞어 단일 피로 원인으로 단정하지 않는다.

불편 보고가 있으면 그 시점과 범위를 먼저 반영하며 목표 시간을 채우라고 요구하지 않는다. 순서 효과를 따로 비교할 필요가 생기면 같은 곡 집합으로 회차/제시 순서를 바꾸고 실제 조건 차이를 기록한다. 다른 곡으로 교체한 구성은 별도 플레이리스트 조합의 비교다.

## 실제 기록에 필요한 필드

현재는 필드 명세이며 가짜 관찰/EXP를 채우지 않는다.

- 대비: plan_id/version, claim_ids, BASE_id, A/B/셀 정의, fixed_fields, deliberate_delta, protocol_type, source_ids, option_ids, 관찰 기준·범위.
- 요청: 이후 실제 EXP_id, 요청 시각/작업 ID, 모델 표시/방식, 모든 입력 전문, 작성/제출/표시 Style, Exclude, 실제 옵션·개인화/보강, 참조 파일/구간, 요청/회차/조건/순서, 예상·실제 비용.
- 반환: 모든 output_id·파일/링크·형식·길이, 정식/preview/중복·오류/응답 불명, 원본/변환본 연결, 원래 음량·비교 gain·재생 환경.
- 관찰: 실제 평가자/도구, 가림 여부, 확인 구간·시간, 개별 요청 충족/대비 성립/동반 변화, T별 근거, 금지 위반·불편/주의/지루함, D판정·범위.
- 요약: 예정/실제 요청·출력 수, 절차 오류와 지시 실패를 구분한 전체 결과, 회차별 혼합/동률·반례, 중단 이유, 남은 질문, 채택/수정/보류·사용자 실제 승인/위임, 다음 조치.

실제 시도와 결과는04에 기록한다. 예정 수치나 이 문서의 예시는 생성 이력/실험 성공으로 등록하지 않는다.

## 완료 판정과 다음 단계

핵심 주장11개에 근거·반대/한계·가능/잠긴 결정을 연결했고, 각 비교의 변경·고정·관찰·실패/중단·필수 입력과 기록을 정했다. **P4의 근거 통합·비교 설계는 제출 가능한 상태다.**

다음 P5에서는 이 기준을 매번 처음부터 설계하지 않도록 '선택지 선택→조합→가장 비슷한 곡 조회→중복/충돌 판정→기록/수정'의 반복 제작 절차로 연결하고, 가상 후보로 통과·실패·미판정 분기를 확인한다. P6에서 첫 제작분과 완결 입력을 준비한다. P1의 계정 전용 공백과 주장별 미해결은 유지하고 관련 결정만 잠근다.
