## 3. 음악적 중심에서 선택지로 옮기는 법

먼저 '어떤 악기를 쓸까'만 고르지 않는다. 예를 들어 '짧은 하행 질문 뒤에 쉼을 두고, 그 빈자리에 베이스가 답하는 관계를 본문에서 되풀이한다'처럼 음악적 사건과 관계를 정한다. 그다음 그 역할을 맡길 악기·연주·음역·발음·음 길이를 선택한다.

현재 선택지 연결:
- 주역/반주/응답/저음/타악/지속 질감: OPT-I01~I10 및 해당 OPT-R.
- 박의 분할·빈자리·베이스 관계: OPT-R01~R05.
- 진행·화음 지속·보이싱/최저음·연결 성부: OPT-H01~H08.
- 중심 음형·리듬 셀·악기 간 전달: OPT-M01~M03.
- 첫 사건·본문 역할·작은 빈자리·마무리: OPT-F01~F05.

선택한 각 OPT에 역할, 필요한 이유, 이번 설계에서의 실제 내용, 출처 ID, 충돌 X와 대안을 연결한다. 연결 어휘를 복사했다고 음악적 사건이 정해지는 것은 아니다. 실제 음표·코드까지 정할 때는 조성/동시음·음역·저음 관계를 대조하고, 아직 정하지 않은 부분은 가정/미정으로 구분한다.

31개 OPT를 모두 쓰거나 모든 곡에 다른 악기를 강제하지 않는다. 같은 편성으로도 본문의 음악 관계가 다를 수 있고, 악기가 달라도 같은 곡처럼 설계될 수 있다. 모든 축을 다르게 해야 한다는 최소 개수·가중치·점수는 추가하지 않는다.

같은 분위기와 반복은 목표의 일부다. 단곡 안의 적절한 반복과 여러 곡의 구별 부족을 혼동하지 않는다. 차별화를 위해 과한 솔로·급격한 상승·드롭·밝은 돌출을 추가하면 공통 목표 위반이다.

## 4. 누적 이력을 조회하는 방법

### 4.1 조회 대상과 용도

| 자료 | 조회 목적 | 유의점 |
|---|---|---|
| 같은 제작분의 활성 설계 전체 | 아직 소리가 없어도 설계 간 복제 찾기 | 직전 곡만 비교하지 않음. 뒤에 후보가 추가되면 앞선 곡도 새 쌍 비교에 포함 |
| 현재 곡의 직전/다음 곡 | 첫 사건·마무리·음색·박·건반 노출의 연속 확인 | 배치 변경은 새 인접 쌍을 다시 확인 |
| 접근 가능한 과거 활성/채택 곡·발매 곡 | 반복되는 중심 아이디어·실제 출력 특징 찾기 | 관련 프로필/비교 목적을 기록. 다른 의뢰를 무조건 비교 코퍼스로 편입하지 않음 |
| 폐기/보류 설계·출력 | 같은 실패·거슬림·미반영의 재발 방지 | 폐기된 모든 시안과 무조건 달라야 한다는 새 금지 목록으로 쓰지 않음 |
| 같은 곡의 이전 버전 | 수정 이유·실패 해결·변경 영향 확인 | 같은 작품의 수정은 별도 신곡으로 세지 않음. 자기 이전 버전과 새로움 경쟁 안 함 |
| 제목/악기명만 있는 과거 기록 | 후속 조회 단서 | 실제 본문 특징/소리를 추측해 채우지 않음 |

### 4.2 실제 조회 순서

1. 조회 시각, 의뢰/기준 버전, 대상 제작분·접근 가능한 파일/인덱스·상태 범위를 고정한다. 없거나 열 수 없는 이력을 따로 적는다.
2. 현재 곡의 동일 계보 이전 버전을 구분한다. 활성 비교 대상·실패 감사 대상·수정 전후 대상으로 나눠 불러온다.
3. 같은 제작분의 활성 후보는 전부 비교 목록에 둔다. 누적 이력은 음형/구절·그루브/베이스·화성 이동/지속·역할·첫 사건 등 여러 경로로 관련 후보를 찾고 합친다. 키/템포/악기 이름 일치만으로 제한하지 않는다.
4. 자동 태그/텍스트 검색은 후보를 찾는 보조 수단이다. 표현이 다르면 놓칠 수 있으므로 실제 특징 서술과 접근 가능한 음원에서 재확인한다. 모르는 특징은 unknown으로 남기며 임베딩/유사도 점수 하나로 최종 판정하지 않는다.
5. 그 범위에서 가장 유사하다고 판단한 후보 ID/버전과 선정 이유를 적는다. 도입·본문·그루브·화성/베이스·역할을 실제로 대조한다. 중요 후보를 좁힐 정보가 없으면 '가장 유사함'도 미판정이다.
6. 비교 목록·제외 이유·누락 범위·자료 수준과 남은 질문을 기록한다. 일부 조회를 '전체 보유곡과 중복 없음'으로 바꾸지 않는다.

첫 후보이고 등록 이력이0이면 현재 컬렉션 내 비교 대상 없음으로 기록한다. 전체 과거 보유곡이 없다고 말하지 않는다. 후보 자체의 목표·충돌 검토는 진행하고 SEED_ONLY로 보존한다. 비교 후보가 생기면 그 쌍을 확인해 범위를 한정한 D06 설계 판정을 갱신한다. 과거 이력을 못 얻었다고 현재 제작분 설계 전부를 중단하지 않는다.

이력이 제목뿐이면 그 과거 비교 판단을 HOLD_D06로 남긴다. 확인 가능한 같은 제작분끼리의 비교 결과는 별도로 보존한다. 실제 음원이 없을 때는 설계 비교이며, 과거 설계가 실제 소리를 대신하지 않는다.

## 5. 비교와 충돌 검수

비교표에는 대상/가장 유사한 후보 ID·정확한 버전·조회 범위·입력 수준(설계/실제 출력)을 먼저 적는다.

| 비교 축 | 적을 내용 | 통과를 대신할 수 없는 것 |
|---|---|---|
| 공통 목표 | T01~T05/T07·해당 T08을 보존하는 구체 설계와 명시 위반 | 개성이 크다는 장점으로 필수 위반 상쇄 |
| 첫 사건/도입 | 무엇이 박의 어디서 시작하고 다른 역할과 어떻게 연결되는지 | 시작 악기 이름만 교체 |
| 본문 개성 | 중심 음형·리듬/쉼·재등장·역할 관계가 어떻게 유지되는지 | 도입만 변경, 동의어 프롬프트 |
| 화성/베이스/그루브 | 진행의 기능·화음 유지/전환·성부/저음 경로·박과의 관계 | 키/템포만 바꾸고 같은 기능·같은 연주 |
| 편성/역할 | 주역/반주/저음/타악의 시간적 관계와 들릴 의도 | 악기만 교체 |
| 건반 단곡/누적 | 음역·음색/발음·전면 배치·구절 노출/쉼·곡 간 연속 | 높은 음 존재만으로 탈락 또는 악기/음량 변경만으로 해결 |
| 충돌 | X01~X09와 관련 원본 Exclude·입력 긴장, 저역/지속 과밀 | 위험 발견을 실제 출력 실패로 보고 |

화성은 가능한 경우 절대 키와 기능/음도 관계를 함께 적고, 음형은 실제 음명과 윤곽/리듬/쉼을 구분한다. 리듬은 BPM과 박 안의 시작·길이·빈자리를 따로 비교한다. 이는 표면 변경을 식별하기 위한 해석 방법이며, 자동 조성 분석의 정확성이나 특정 음형의 독창성을 보장하지 않는다.

가장 유사한 후보와 공통인 부분, 도입 차이, 본문에 남는 차이, 공통 목표 보존, 미확인 범위를 한 기록에 남긴다. 한 요소를 공유한다는 이유만으로 탈락시키지 않고, 구체적으로 설명할 지속 차이가 없으면 수정한다.

현재 원본 Exclude의 snare 전체 제외와 brushed drums의 잠재 긴장은09/13대로 보존한다. '조용한 브러시니까 예외'로 몰래 완화하지 않는다. 명시적으로 함께 요구한 내용이 충돌하면 해당 입력을 해결하고, 해소 전에는 완결 프롬프트 준비라고 하지 않는다.

## 13. 묶음 제작/생성 — 0.17.0 사용자 지시 우선 적용

- 묶음시작에최신02·18·대상전체설계를읽고공통기준/버전과조회범위를고정한다.곡별전체입력/개성/가장유사한후보·명시충돌을한꺼번에검토하고기록한다.
- 같은판본이유지되는묶음안에서는곡마다문서전체재작성/사용자확인/전체ZIP갱신을반복하지않는다.입력직전동일기준/기록판본과대상문안의지문·길이·실제필드/설정을짧게대조한다.
- 기준/등록전문/설계/설정이바뀌면영향받는검토를갱신한다.공통분위기와실제차이검사를생략하거나곡이름/악기명만으로합격시키지않는다.
- 명시된묶음생성허용범위안에서각문안한번씩생성하고모든반환결과를보존한다.오류/요청결과불명은맹목적으로다시클릭하지않는다.크레딧부족/허용범위밖구매는중단해알린다.
- 실제반환/기록검수후사용자에게한번에듣기목록을제공한다.사용자피드백을모아해당곡만수정하며,좋은후보가나올때까지임의재생성을반복하지않는다.
