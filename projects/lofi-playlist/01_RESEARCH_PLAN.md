# 조사 계획

문서·운영 판정 버전 0.4.2 / 음악·요구 의미 기준선 0.4 / 2026-10-27 / 상태: 원본 문구·P1 공개 사실·P2 사례·P3 선택지를 P4 근거 통합/비교 계획으로 연결. P5 접수·반복 제작/중복 검수 절차 제출; P6 첫20곡 설계 범위 제출; 다음 통합 입력

작성·재검수 기준선: 02 문서 부록 A의 R01~R22 및 06 문서 G01~G10(0.4). 상세 자료 판정의 정본: 06_SELECTION_CRITERIA.md. 조사할 항목의 존재만으로 검수 통과를 선언하지 않는다. 이하 표의 완료 조건은 그 문서의 E유형·D결정·READY 조건을 모두 충족해야 성립한다.

현재 작업의 실행 가능 범위는 유효한 누적 작업 지시와 최신 변경·중단 지시를 함께 적용하고, 진행 상태는 05가 정본이다. 상태 질문·중간 설명 요청만으로 기존 허용 범위를 취소하지 않는다. 기준 원본 확보를 먼저 시도하되 미확보 때문에 독립된 제품·사례·음악 조사를 모두 중단하지 않는다. 입력별 진행/보류는 02 §5, 전체 적용 요약은 02 §6을 따른다.

현재 P1 조사 결과의 정본은 10_PRODUCT_CAPABILITIES.md다. 03에 실제 검색/출처/주장,05와 상태 파일에 공개 사실·전체 질문 상태·다음 작업을 기록한다. 개별 사실의 READY를 P1 전체 완료로 취급하지 않는다. P2의 이번 사례 탐색·공개 정도 분류는11_CASE_RESEARCH.md, 사례 원장은03이다. P3 음악 선택지와 조합/충돌의 정본은12_MUSICAL_OPTIONS.md, 선택지 근거 원장은03이다. P4 주장별 판단·비교 계획의 정본은13_EVIDENCE_AND_TEST_PLAN.md다. P5 반복 제작/중복 검수 절차의 정본은15_REPEATABLE_PRODUCTION_WORKFLOW.md이며 다음은 P6 첫 제작분 설계/입력 준비다. 단, P1/P2 전체나 실제 실행 단계의 통과 이벤트를 임의로 기록하지 않는다.

## 의뢰의 시작과 음악 목표의 적용

접수·방향 탐색·선택/위임·변경/재개의 정본은14_REQUEST_INTAKE.md다. 기존 작업과의 관계와 방향의 구체성을 별도로 판단한다. 공통으로 재사용하는 것은 절차이며02/06의 음악 내용은 현재 lo-fi 프로필이다. 방향이 없으면 탐색으로, 일부 아이디어가 있으면 그 단서를 보존한 탐색으로 시작한다. 현재는 기존 요구를 불러와 P5 후속 설계를 계속할 수 있고 P1~P4를 다시 시작하지 않는다. 접수 보완만으로 P5 전체 완료를 선언하지 않는다.

## 현재 P6 인계 상태

첫20곡의 곡별 설계·현재 제작분 D06 비교/충돌·순서/노출 검토는16_FIRST_BATCH_DESIGNS.md와 first_batch_designs.json에 등록했다. 실제 제작 기록 인덱스는04다. 이번 사용자 요청은 곡별 설계이며 전체 프롬프트/계정값/실제 실행은 확정하지 않았다. P6 전체는 부분 진행이며 다음은1번부터 통합 입력 작성이다. 기존 P1/P2 잠금은 영향받는 결정만 유지한다.

## 조사 목표와 범위

목표는 특정 문구의 만능 해법을 찾는 것이 아니다. 공통 청감을 보존하면서 음악적 구성을 바꿀 수 있는 선택지와 조건을 근거에 따라 정리하고, 반복 제작에서 사용할 판단 절차를 만든다.

프롬프트 본문·제외 문구·모델·생성 방식·추가 옵션·참조 오디오를 하나의 생성 조건으로 기록한다. “논문 수준”은 긴 글이나 긴 검색 시간을 의미하는 것으로 취급하지 않는다. 질문의 명확성, 검색 경로, 자료의 출처, 누락·상충 근거, 검증 범위가 추적 가능한 조사로 구현한다. 동료 심사를 거친 논문과 동등한 결과라고 표현하지 않는다.

## 수집 순서

1. 원본·실제 설정·승인 음원을 기존 자료에서 먼저 확보하려 시도한다. 미확보는 가정으로 메우지 않으며 최종 청감 판정만 보류한 채 선행 사실 조사는 진행할 수 있다. P1에서 모델과 입력 구조를 확인한다. 제품의 현재 기능 확인에는 공식·현재 화면 자료를 우선 사용하되 소리의 제어 성능을 증명하는 자료로 확대하지 않는다.
2. P2에서 조건이 공개된 소수의 사례부터 기록 양식에 넣어 누락·모호성을 확인한다. 그 후 성공·실패·비교·반례로 범위를 넓힌다.
3. P3에서 편성만이 아니라 연주·리듬·화성·도입·전개까지 조사한다. 음악적 적합성과 모델의 실제 지시 반영은 다른 질문으로 다룬다.
4. P4에서 근거가 약한 핵심 주장과 제작 결정에 영향을 주는 공백을 먼저 보완한다. 같은 주장만 반복되는 검색을 자료 수 늘리기로 이어가지 않는다.
5. P5 이후에 곡별 설계와 프롬프트로 번역한다. 지금 제시된 과거 20개 시안을 검증된 후보군으로 재사용하지 않는다.

## 검색 계획과 자료 채택

기준을 수립하거나 분석할 때 웹 검색을 기본으로 적용한다. 관련 방법·반례·적용 한계를 먼저 확인하고 03에 기록한다. 기존 사용자 취향/목표를 외부 자료로 덮어쓰거나 외부 자료를 Suno 효과 검증으로 확대하지 않는다. 이번 원본 분석의 실제 적용은 09 및 06 §11을 따른다.

영문·국문 검색을 모두 사용한다. 최초 검색식 후보는 Suno muffled lofi prompt, dark warm jazzhop, underwater lo-fi, too bright lofi, same piano intro, 옵션명 + model/version + comparison 등이다. 검색 시 실제 사용한 쿼리·날짜·범위·결과·추가 검색 이유를 03 문서에 기록한다. 이 문장의 검색식은 계획 후보다. 실제 실행 이력은 03의 SEARCH 기록을 따른다.

- 커뮤니티는 Reddit 등 사용자가 실제로 투입한 조건과 결과가 있는 글을 우선한다. 실패 사례와 반대 결과도 포함한다.
- 음악 원리·악기 특성은 제작자·악기 제조사·교육기관·연구 등 출처의 성격을 확인한다.
- 프롬프트 모음, 홍보 글, 출처 없는 팁은 탐색 단서로는 쓸 수 있으나 검증된 해법으로 채택하지 않는다.
- 오래된 모델의 결과는 당시 조건을 기록한다. 현재 모델의 효과로 자동 일반화하지 않는다.
- 검색되지 않거나 삭제·로그인 제한·오디오 접근 제한이 있는 경우 미확인으로 기록한다. 빈칸을 추정으로 메우지 않는다.
- 근거가 독립적인지 확인한다. 같은 게시물을 재인용한 여러 문서는 여러 번의 실험이 아니다.

## 검증 설계 원칙

실제 생성 실험이 필요하면 기준 원본과 비교 대상, 바꿀 변수, 고정할 조건, 반복 시도, 청감 평가 항목, 비용을 사전에 기록한다. 같은 프롬프트에서도 결과가 달라질 수 있으므로 단일 출력 차이를 인과 효과로 확정하지 않는다. 시드 등 재현 기능은 존재 여부부터 확인한다. 여러 출력을 생성했으면 좋은 것만 남기지 말고 전체 시도와 채택 기준을 기록한다.

이 계획 문서만으로 유료 생성·사용자 크레딧 사용을 실행하지 않는다. 이후 실제 생성 지시가 있으면 그 허용 범위와 비용 조건을 기록한다. 직접 생성하지 않은 단계에서는 “음악적 설계 검토”, “문구 검토”, “사례 조사”라고 보고한다.

## 범위 종료·갱신

질문은 해당 E/D 요건을 충족할 때 READY, 근거로 적용되지 않음을 확인했을 때만 N/A로 둔다. 미확인 이유·상충·다음 조치만 기록한 질문은 UNRESOLVED이며 관련 결정을 잠근다. 검색 중단과 조사 완료를 구분한다. 시간·게시물 수만으로 충분성을 주장하지 않는다. 핵심 불확실성이 남으면 부분 완료로 둔다. 모델·UI·생성 방식이 바뀌거나 실제 결과가 기존 판단과 충돌하면 관련 항목만 재확인하고 영향을 받는 기준과 제작 기록을 갱신한다.
## 사전 선별 적용

수집할 때마다 연결 질문·주장을 정하고 06 문서 E01~E06의 필수 조건을 대조한다. CORE/SUPPORT/LEAD/HOLD/EXCLUDE와 이유·허용 용도를 기록한다. 공식 설명은 제품 사실에, 악기 자료는 음악적 적합성에, 실제 생성 비교는 공개 조건에서의 관찰에 사용한다. 미공개 설정이 있는 사례를 정확한 기본값의 근거로 승격하지 않는다.
## 0.4 추가 조사·검수 목표 — 건반의 반복 청취 적합성

R22/U11/T08을 Q06~Q11에 연결한다. Q06~Q07에서는 높은/선명한 건반이 반복돼 거슬린다는 실제 사례와 수정 시도를 수집 대상으로 삼는다. Q08은 음역과 음색·발음을 분리하고, Q10은 보이싱·반복 음형·쉼, Q11은 곡 간 누적 반복과 순서의 선택지를 조사한다.

관련 사례에서는 실제로 확인한 청취 구간·시간, 작성자의 주관적 보고, 수정 전후 조건을 분리한다. 일반적인 피로 효과나 특정 주파수·옥타브의 정답을 이미 검증한 것으로 취급하지 않는다. 음악 목표 U11과 조사 방법 U07을 같은 유형의 조건으로 평가하지 않는다. 현재 자료/계획의 최신 상태는12/13과05를 따른다. 실제 누적 청취 기록은 별도다.
## 레드팀 보완 — 자료 조사와 생성 검증의 의존성

P2의 검색 범위 검토 종료, 각 주장의 READY/UNRESOLVED, 실제 생성 검증 상태를 따로 기록한다. 자료가 부족한 주장은 미해결로 남기고 관련 사실 확정은 보류한다. 미해결 이유만 적어 READY로 바꾸지 않는다. 다만 미해결 효과의 시험 방법을 P4에서 계획하고, 그 효과를 검증된 것으로 전제하지 않는 P6의 시험용 설계를 진행할 수 있다. D04는 실제 반복 생성 비교 이후의 판정이며 P2를 끝내기 위한 선행 생성 의무가 아니다.

새 조합의 공개 사례가 없으면 D03의 EXPLORATORY 유형으로 입력·가설·평가 계획을 기록할 수 있다. 이는 검증된 추천이나 생성 실행 허가가 아니다. 실제 생성은 기존에 허용된 범위에서만 수행한다.
## 문서 변경 후 실행 검증

작성·수정·제출 절차는 00의 작업 방식 0.5.0을 따른다. 이 문서는 그 절차를 따로 재정의하지 않는다. 상태 파일 workflow.phase_dependencies는 단계 이동을 검증하기 위한 실행 의존 관계다. P2_SCOPE는 검색 범위 검토 이벤트이며 효과 주장 READY나 P2 전체의 효과 검증 완료가 아니다. 미해결 주장은 그대로 두고 검증 계획을 작성할 수 있다. 실제 생성 실행 범위는 별도 사용자 지시를 따른다.
