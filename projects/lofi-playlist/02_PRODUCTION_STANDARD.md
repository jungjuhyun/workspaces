## 2. 음악 목표와 비교할 항목

공통 목표는 먹먹하고 어둡고 따뜻한 청감, 둥근 발음, 존재감 있는 저음, 뒤에 놓인 조용한 타악기, 낮은 에너지의 연주곡이다. 그 안에서 곡마다 도입과 지속되는 음악적 개성이 달라야 한다. 이번 20곡은 첫 분량이며 반복 제작에 재사용한다.

상세 음색 목표 대부분은 앞선 인용 분석에서 승계한 것이다. 현재 원본 Style·Exclude는 이전 대화에서 회수했으나 실제 설정·승인 음원은 미확보다. 건반의 장시간 거슬림 방지는 사용자님이 명시한 R22다. 정량 허용 정도를 이미 확정한 것으로 취급하지 않는다.

### 현재 우선 수정 — FB-000002 / INTRO-DRUM-0001 / 2026-10-28

사용자는 도입 이후 서로 다른 코드 진행은 마음에 들지만, 첫 약3초의 건반 음·연주 방식과 피아노→드럼/동시 진입의 반복, 드럼 패턴·질감의 유사성을 보고했다. **좋은 본문 화성과 분위기는 유지하고 해당 요소를 집중 수정한다.**

- 도입은 첫 악기만 정하지 않고 음정 윤곽·단음/동시 화음·리듬·발음·쉼·진입 관계를 함께 설계한다. 같은 세 음의 조옮김이나 드럼 지연만으로 구별 완료를 판정하지 않는다.
- 드럼의 박 위치·분할·강약·빈자리와 재료·어택·몸통·감쇠를 따로 적는다. 조용함/뒤에 배치는 공통 믹스 목표이며 동일한 소리라는 조건이 아니다. 차이는 도입 뒤 본문에도 유지되어야 한다.
- 모든 피아노 선행/동시 시작을 금지하지 않는다. 두 공식에 몰리고 실제로 같은 곡처럼 들리는 문제가 수정 대상이다. 같은 습관을 세 음에서 네 음으로 옮기는 것도 해결이 아니다.
- R23 건반 주역과 기존 Exclude를 유지한다. 밝고 센 드럼으로 바꿔 차이를 만드는 우회는 사용하지 않는다. 피아노가 첫 소리가 아니어도 본문 주역은 건반이다.
- 과거 문안을 새 생성에 복사하기 전 이 항목을 검토한다. 건반 주역 적합 상태는 도입·드럼 재사용 승인과 다르다. 다운로드/채택 후보 번호가 미지정이므로 기존 음원을 전부 탈락/전부 승인하지 않는다.

기존 R01·R05·R08 및 U03/U04/T06의 실제 피드백에 따른 구체화다. 새 요구 번호를 늘리거나 본문 코드를 재설계하지 않는다. 비교 방법은20, 전문 누적은18 PRM-000023~000026, 원문 보고는04 FB-000002.

## 3. 건반의 반복 청취 적합성 — U11/T08

이는 사용자님의 관찰과 제작 목표이며 모든 사람에게 특정 소리가 일정 시간 후 반드시 피로를 일으킨다는 일반적 사실이 아니다.

| 축 | 확인할 내용 | 기록·수정 방향 |
|---|---|---|
| 음역 | 높은 건반 음이 주선율·반복 음형의 중심에 계속 놓이는가 | 중저역 배치를 우선 검토하되 높은 음 자체를 일괄 금지하지 않음 |
| 음색·발음 | 같은 음높이에서도 너무 또렷하고 날카로운 시작·벨 같은 밝은 울림이 반복되는가 | 음높이를 낮춘 것과 음색이 부드러워진 것을 구분 |
| 단곡 반복 | 해당 소리가 얼마나 자주·오래·앞에서 반복되는가; 쉼과 다른 역할의 균형은 어떠한가 | 문제에 맞춰 음형·밀도·쉼·배치를 조정. 안정적인 편성을 불필요하게 계속 교체하지 않음 |
| 플레이리스트 누적 | 비슷한 건반 음역·어택·울림·음형이 여러 곡에서 연속되는가 | 악기 이름만 달라졌는지와 실제 소리의 차이를 구분하고 곡 순서도 검토 |

높음·선명함·반복·주의를 끄는 소리의 발견은 **위험 검토 신호**다. 그것만으로 자동 탈락시키지 않는다. 확인한 소리가 목표와 어긋나거나 사용자님이 거슬림·피로를 보고하면 해당 범위를 수정·재평가한다. 높은 음 전체 금지, 모든 건반 금지, 모든 소리의 과도한 필터링을 추가 조건으로 만들지 않는다.

수정은 음역·보이싱·발음·음색·전면 배치·반복 밀도·쉼·곡 순서 중 실제 문제에 해당하는 요소로 한다. 음량이나 악기 이름만 바꿨다고 해결을 선언하지 않는다.

직접 확인한 파일·구간·누적 시간·재생 조건·평가자를 기록한다. 짧은 구간 확인을 1시간의 편안함으로 확대하지 않으며, 실제 확인하지 못한 장시간 적합성은 미판정이다. 주파수·옥타브·반복 횟수·시간 경계값을 근거 없이 만들지 않는다.

## 4. 곡 설계와 생성 조건을 분리해 기록

### 4.2 생성 환경·입력 조건

모델 표시명·버전·생성 방식·입력 전문·추가 옵션·참조 오디오와 구간·실제 입력 제한을 음악 내용과 별도로 기록한다. 계획한 조건과 실제 입력을 구분하며 미확인 값은 빈 사실로 남긴다. 현재 제품 사실의 확인은 01 Q01~Q05와 06 D01을 따른다.

프롬프트 수정 시 Style·필요한 Lyrics/구조 지시·Exclude·설정을 통합 전문으로 제공한다. 실제 코드·템포·입장 시점은 입력한 내용과 출력의 반영 여부를 분리한다. 58~76 BPM·65 BPM·F장조·Rhodes는 전곡에 고정할 사용자 조건이 아니다.

## 6. AI가 적용할 순서 — 01 조사 계획의 실행 요약

1. 유효한 누적 작업 지시와 최신 변경·중단 지시, 00·05를 읽어 허용 범위·미완료 항목을 확인한다. 상태 질문에는 답한 뒤 기존 허용 작업을 계속한다. 문서 검토 요청을 웹 수집·유료 생성 지시로 확대하지 않는다.
2. 이 문서의 목표와 §5 입력 상태, 06의 해당 조건을 확인한다. 기존 원본·설정·승인 음원을 먼저 찾고 확보한 내용만 분석한다.
3. 조사가 허용된 경우 01의 모델/입력 조건 → 실제 사례 → 음악적 선택지 순서와 선행 관계를 따른다. 원본 미확보 분기는 §5대로 처리한다.
4. 근거와 이력을 사용해 곡별 설계·플레이리스트 순서를 작성하고 04에 기록한다. 모든 요구에 관련 근거와 판단 범위를 연결한다.
5. 설계 차이·공통 청감·입력 충돌·통합 전문·현재 입력 제한을 검수한다. 통과는 시험용 설계/프롬프트 준비를 뜻하며 소리 합격이 아니다.
6. 실제 생성이 허용되고 출력을 확보한 경우에만 직접 확인·비교한다. §7처럼 설계·청감·장시간 적합성·사용자 채택을 별도 상태로 기록한다.
7. 03의 근거, 04의 설계/결과, 05의 진행·미해결과 상태 JSON을 갱신하고 06 G조건으로 제출 전 재검증한다.

단계별 세부 입력·산출·완료 조건의 정본은 01 및 06이다. 이 순서는 파일의 문단 배열이나 R/U 번호를 작업 순서로 오해하지 않도록 하는 요약이다.

- 승계한 음악 목표: 먹먹하고 어둡고 따뜻한 질감, 둥근 발음, 존재감 있는 저음, 조용한 타악기, 낮은 에너지, instrumental. 이전 답변의 원본 분석과 이를 전제로 한 사용자 발언에서 이어진 목표다. 정확한 원본 전문·음원·설정이 없으므로 각 표현의 원문 출처와 허용 정도를 직접 재확인한 것처럼 말하지 않는다.
- AI가 설계한 방법: E/T/D 분류, CORE 등 판정명, 식별자 체계, 문서 구성, 기준 음원·비교 구간 확보 절차, 단계명, 가상 판정 사례. 사용자 요구를 구현하는 운영 제안이며 사용자 원문 요구나 실험으로 확인된 사실이 아니다.
- 관련 상시 선호: 음악 프롬프트를 수정할 때 통합 전문·필요한 제외 전문을 제공한다. 이후 프롬프트 작성 단계에 적용한다. 다른 가사·앨범 프로젝트의 조건을 이 lo-fi 연구에 전이하지 않는다.
- 미확정 사실: 원본 전문·실제 모델/설정·승인 음원/구간·현재 제품 기능·음향 허용 경계·허용 템포 범위. 요구사항 누락과 필요한 입력 미확보를 구분한다.
